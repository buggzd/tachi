# 实时 SBS 优化论文调研与实验设计

日期：2026-09-11。代码基线：`799661e`。本轮未连接、安装或操作手机，也没有新增
性能或画质实测。此文是研究候选，不是已落地功能或性能承诺。

## 结论与约束

优先保留已经跑通的 Depth Anything V2 Small / QNN 路线，探索“低频估计场景结构，
高频更新用于显示的视差”。最值得先做的是时间一致的尺度处理、带可信度的运动传播、
保边上采样，以及取帧/推理解耦。直接提高模型输入分辨率或换大视频模型不是首选。

用户偏好保持上一张有效深度，允许少更新，避免自动切回平面。该偏好继续成立。
低可信度处理应保持/有界更新已有视差，而非把整幅画面突然置零。seek、片源切换、
关闭转换等显式生命周期边界仍需丢弃不属于当前画面的历史。

产品继续保持一个 glasses WebView、一个 HTML video、一条音频/播放上报链路。
不能把第二个 MediaCodec 播放器或屏幕录制当作无代价的取帧优化。

## 已阅读资料与可迁移结论

### 1. Video Depth Anything，CVPR 2025

论文：[2501.12375v2](https://arxiv.org/html/2501.12375v2)，重点为 §3.1–3.3、附录限制；
[官方实现](https://github.com/DepthAnything/Video-Depth-Anything)。

- 在 Depth Anything V2 的 DPT 头低分辨率特征处插入时间注意力，联合图像/视频训练。
- 原论文采用 32 帧窗口、重叠帧与历史关键帧，进行 scale/shift 对齐和窗口衔接。
  “支持任意长视频”不等于逐帧因果流式输入；原论文将 streaming 列为后续工作。
- 后续官方实验流式版本缓存 temporal attention 隐藏状态，每次输入一帧；README
  明确报告训练/推理分布差异，例如 ScanNet δ1 从 0.926 降至 0.836。
- Small 为 28.4M 参数。README 的延迟/显存表来自 A100、1×32×518×518 输入，
  不能当作手机单帧端到端延迟；Small 的 Apache-2.0 与 Base/Large 的 NC 条款也不同。

对 tachi：可以先借鉴历史锚点和跨帧尺度对齐。直接替换模型需验证静态缓存输入输出、
时间模块算子支持、QNN 全图执行、量化误差与流式精度，不能假定现有 ONNX 能直接替换。

尤其重要：论文指出光流对应点的真实深度也可能变化，例如相机向前运动。
因此“让光流对齐后的深度永远不变”不是正确优化目标，可能把真实运动压平。
TGM 是依赖训练真值的损失，不是可以直接贴到运行时的滤镜。

### 2. FlashDepth，ICCV 2025

论文：[2504.07093v2](https://arxiv.org/html/2504.07093v2)，重点为 §3.2–3.5、§8.2；
[官方实现](https://github.com/Eyeline-Labs/FlashDepth)。

- 使用因果 Mamba 隐藏状态处理低分辨率 DPT 特征，产生残差修正，保留基础模型能力。
- 高分辨率轻模型与低分辨率强模型并行，以 cross-attention 融合结构与细节。
  这仍有两条模型计算路径，不是简单将低分辨率深度放大。
- 论文报告 A100 上约 24 fps、2044×1148。计时前已预处理所有输入并放入 GPU 显存，
  不包括 tachi 的 WebView 解码画面读取、跨桥和两眼呈现。
- 官方代码依赖 Mamba/CUDA 工具链，并注明 temporal 模块位置较论文有所调整。

对 tachi：有价值的是“低维状态负责时间连续性，高分辨率路径负责边界”的分工。
直接移植 Mamba 或双模型目前风险较高；QNN 支持与完整设备成本尚无证据。
可作为后续轻量因果学生模型/时序头训练的参考，而不是立刻替换现有后端。

### 3. RollingDepth / Video Depth without Video Models，CVPR 2025

[官方论文项目与方法说明](https://rollingdepth.github.io/)，
[论文](https://arxiv.org/abs/2411.19189)。本轮阅读官方方法说明，未完整审阅其附录。

对很短片段联合估计深度，再对不同采样跨度的片段做全局尺度/偏置注册；说明长视频
不稳定不仅是像素噪声，也有整体尺度漂移。其扩散模型与全局优化流程不适合直接搬到
手机低延迟播放，但可以作为离线参考输出或教师候选。教师输出也不是几何真值。

### 4. Fast Optical Flow using Dense Inverse Search，ECCV 2016

[论文全文](https://arxiv.org/html/1603.03590)：patch inverse search、多尺度传播、
稠密聚合及可选变分细化；不同配置有速度/精度取舍。

适合用作无需训练的低分辨率运动传播候选，与 StereoLab 现有运动模块比较。
论文的 CPU 速度来自其桌面实验，不能引用成当前手机结果。必须计入运动缩略图的
采集成本，测试前后向一致性、遮挡、新显露区域以及动画片低纹理/重复线条。

### 5. Joint Bilateral Upsampling，SIGGRAPH 2007

[作者项目与摘要](https://johanneskopf.de/publications/jbu/)。

用高分辨率图像作引导，将低分辨率求解结果提升到高分辨率。对应 tachi 的直接用途是
让深度边缘跟随同帧 RGB 边缘，替换纯双线性采样，而非让 NPU 对每个显示像素推理。

### 6. Guided Image Filtering，ECCV 2010 / TPAMI 2013

[作者方法说明、论文与代码入口](https://people.csail.mit.edu/kaiming/eccv10/index.html)。

利用引导图的局部线性模型保边，作者提供关于像素数量的线性时间算法，也列出
Fast Guided Filter。适合与 joint bilateral 做桌面边界/成本对照。

两类保边方法的共同边界：RGB 纹理不等于真实几何边缘；会有纹理泄漏，也无法恢复
低分辨率模型根本没有识别出的细线。不能称为真正的高分辨率深度估计。

### 7. FastDepth，ICRA 2019

[作者项目与论文入口](https://fastdepth.mit.edu/)。阅读作者摘要与架构概述。

轻量 encoder/decoder、低延迟解码头和剪枝说明模型部署必须优化整个结构，不能只看
参数量。报告的 Jetson TX2 GPU 178 fps、CPU 27 fps、NYU Depth v2 精度来自不同
硬件/数据域，不能说明该模型适合电影、动画或当前 QNN。优先借鉴蒸馏、轻量头和
硬件实测选型方法，而非直接采用旧室内模型替换通用模型。

## 当前实现的可量化空间

### A. 固定平滑系数可能引入新的慢响应

当前范围更新系数为 0.15；外观稳定且深度变化小于 0.12 的像素系数为 0.35。
对 EMA，等效时间常数为：

`τ = -Δt / ln(1 - α)`

在约 8 fps、Δt≈125 ms 下，分别约为 769 ms 和 290 ms。这不是额外推理时间，
而是阶跃响应滞后；帧率降低时，固定系数会使恢复更慢。阈值也可能让像素在“平滑”
和“直接采用新值”间切换，产生不连续响应。

候选：按媒体时间差设置 `α(Δt)=1-exp(-Δt/τ)`；时间常数取 80/160/320 ms 做消融，
不能预先宣布某个数最舒适。对稳定背景与运动/遮挡区分别计算权重，而不是仅看同一
屏幕坐标 RGB 差。动画同色物体运动时，现有外观阈值可能误判为静止。

### B. 先对齐同一个物体，再平滑深度

令模型新深度为 `D_t`，历史稳定结果为 `S_(t-1)`，光流后向采样得到：

`P_t(x) = S_(t-1)(x + F_(t→t-1)(x))`

在可信对应区域，以有正尺度约束、鲁棒残差和历史正则估计 `a_t,b_t`，对齐
`a_t D_t+b_t` 与 `P_t`；不要继续让每帧 P5/P95 独立决定整幅视差范围。
随后用可信度加权融合：

`S_t(x) = w_t(x) (a_t D_t(x)+b_t) + (1-w_t(x)) P_t(x)`

前后向光流误差、光度残差和遮挡决定可信度。新显露区域优先新深度，不传播不存在的
旧表面；只有旧深度时保留已有视差，等待新推理修正，避免整幅归零。切镜应分段重置
注册历史，不把旧场景传播到新场景；如何过渡到首张新深度需单独评估，不能恢复周期
性平面回退。

真实物体前后运动也改变深度，所以全局仿射对齐只能是有限权重的漂移校正，不能把
新图强制拟合到旧图。低纹理、对应不足时不更新校准参数；锚点与有界历史用于控制
累计漂移。纯静止深度也会得到很低的帧间差，必须同时测动态跟随能力。

### C. 推理帧率不必等于显示更新帧率

候选双频管线：24 fps 视频使用轻量运动传播更新视差，NPU 以 8/12/16 Hz 补充结构。

旧结果必须带捕获的媒体帧时间：推理 `I_k` 的结果到达当前 `I_t` 后，要通过有界历史
映射到当前帧，而不是只 warp 一次相邻帧就认为已追上。队列只保留最新候选，避免
“异步化”变成几百毫秒的排队。资源不足时丢推理任务，不累积旧任务，不跳回 2D。

以此前约 31 ms 原生服务时间举例，12 Hz 约占 372 ms/秒的串行服务时间；这不是
NPU 利用率或功耗测量。若光流/传播另需每显示帧数毫秒，它们仍可能占满 GPU/CPU，
尤其不能为每帧运动再增加一次昂贵视频读回。优先复用模型帧，独立测量非模型帧的
缩略图读取。StereoLab 已有运动传播原型，但不等于 Android 集成已经具备该能力。

### D. 先改善低分辨率边界，再决定是否提高模型分辨率

266×154 到每眼 1920×1080，横向放大约 7.2 倍；可以比较双线性、joint bilateral、
guided filter，以及更高输入尺寸。提高分辨率会增加模型计算、读回和跨桥负担；
ViT 成本不能简单保证按像素数量线性增长，量化模型还需要重新导出/校准。

推荐先以 266×154 深度生成约半分辨率的保边视差，再用于双眼采样。不要在每眼、
每个 gather 候选里重复完整保边滤波。引导图必须对应模型捕获帧或经过运动对齐；
旧深度直接用新视频引导，可能把错误边缘锐化得更明显。

### E. 绘制算法也有优化空间

当前每眼全像素搜索 33 个源位置。若两个 1920×1080 画面全部进入循环，上界为
约 1.37 亿次深度候选查询/视频帧。UI/边界早退、缓存与编译器优化会改变实际成本，
这不是 GPU 带宽或耗时估算。

平滑区域可以研究逆投影迭代：

`q_(j+1) = x - s A (n(q_j)-0.5)`

在 `|A ∂n/∂x|<1` 区域有局部收敛依据；边界/遮挡不满足此条件，必须保留局部搜索
或可见性解析。比较 2/4 次迭代与现有 33 候选的像素误差、覆盖和遮挡，而非只看速度。
另一候选是在较低分辨率预计算左右采样映射，显示阶段只采样一次；需控制边界泄漏。
这些是结合现有代码的工程推导，不是上述论文已验证的 tachi 算法。

### F. 取帧与传输往往比改模型更紧迫

既有实测的 CPU drawImage 约 20–31 ms，原生处理约 31 ms；GPU Canvas 对照把
等待移到 getImageData，并没有消除它。两项串行的 51–62 ms 已超过 24 fps 的
41.7 ms 预算，尚未计桥、调度和最终呈现。这些数字来自不同窗口，只用于量级分析。

若能真正重叠独立阶段，稳态周期理论上由“各阶段之和”趋向“最慢阶段”，但单帧
延迟不会自动变成最大值，共享 GPU 带宽也会限制收益。候选是 GPU 先降采样、异步
读回/有界双缓冲、Worker 帧处理、减少不必要的数据复制。PBO/fence 不等于零拷贝，
不能调用后立即阻塞等待而宣称异步成功。

当前 HTML video/WebView 并未向 Java 直接交付可供 QNN 使用的解码纹理。
直接 NPU/GPU 共享缓冲是架构研究项，不是当前桥上加一个开关就能获得的能力。
Base64 载荷约 218 KB/帧，在 24 Hz 约 5.24 MB/s；它有复制和分配成本，但既有
btoa 样本不到 1 ms，不能仅凭数据量就把它排在已测数十毫秒的读回之前。

## 桌面阶段的实验顺序

| 优先级 | 消融实验 | 指标与淘汰条件 |
| --- | --- | --- |
| P0 | 固定 α vs 按时间 α；0.15/0.35 当前基线 | 静态抖动、真实深度阶跃跟随；不能以过度迟滞换取低抖动 |
| P0 | 保持旧图 vs DIS/现有运动传播；原始/鲁棒尺度对齐 | 运动轮廓错位、可信区域 warp 残差、新显露区域错误、切镜残留 |
| P1 | 双线性 vs joint bilateral/guided；同输入分辨率 | 深度边界 F1、细线保留、纹理泄漏、额外处理时间 |
| P1 | 33 候选 vs 混合逆投影/预计算映射 | 左右方向、遮挡、覆盖、UI/letterbox 不变、输出像素误差 |
| P1 | 原始取帧 vs 异步/共享读回 | 实际等待位置、排队帧龄、帧提交率、内存上界，不只看函数提交耗时 |
| P2 | VDA-S 流式或轻量因果头 | 先验证导出与 QNN 算子/量化，再测单设备端到端；不接受隐式 CPU 回退 |

使用静态几何、已知匀速平移、物体前后运动、遮挡/显露与切镜的合成序列建立真值，
再加动画、真人、快速横摇片段。不以“整帧平均亮度差”代表几何稳定。

核心指标应换成可见视差：当前 `u=sA(n-0.5)`，A 最大 30 源像素。深度误差 0.02
对应单眼约 0.6 源像素，最终还受虚拟银幕缩放影响。记录稳定区域视差抖动 P95、
运动边界错位、切镜恢复时间、遮挡破损、深度帧龄、运动传播帧率和实际新推理帧率。
可先以单眼稳定区 P95 0.5 源像素为探索门槛，但它不是已验证的舒适度阈值。

真实光学体验、Android HWUI/GPU 吞吐、QNN 并发与非充电热态只能待手机恢复后验收。
本轮推荐先做 P0 的离线对照，不增加模型尺寸，也不重新开启正常慢帧的平面回退。
