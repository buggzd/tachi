# 实时 SBS 主技术路线

2026-09-15 决定：以 **392×224 严格同帧深度 + GPU 背景局部液化** 作为 tachi 后续实时 3D 的主技术路线。依据是用户对当前观看效果的确认，以及原生链路已运行的证据；[最新复测](performance/2026-09-15-native-liquid-retest/README.md)仍为部分通过，主路线选择不代表全部设备验收或发布默认切换。

## 固定基线

| 项目 | 主路线约定 |
| --- | --- |
| 深度 | Depth Anything V2 Small，QNN HTP，392×224 |
| 深度范围 | 每帧精确 P2/P98 映射；不做范围 EMA 或像素历史融合 |
| 时序 | 深度与生成它的 RGB 严格配对，完成后整对提交；无固定延后两帧 |
| 几何 | GPU 背景局部液化；强度 0.85，羽化 96 px，拉伸 65% |
| 坐标 | 羽化按每眼 1920 源宽定义，随实际源宽换算；不是 SBS 总宽或手机 CSS 像素 |
| 节拍 | 24 Hz 调度目标；忙时重复有效成对画面，接受更新率降低 |
| 禁止的自动降级 | 不用旧深度配新视频，不自动压平深度，不回退 CPU 推理 |
| 控制与字幕 | 原生单播放器；WebView 仅目录/控件/字幕，字幕优先用配对位置 |

## 实现与取舍

```text
Media3 / MediaCodec → OES 视频纹理
                     ↓ 同源 PTS + 有界捕获槽保留全尺寸 RGB
GPU 小图 CHW / 标准化 → 主机缓冲 → QNN HTP 深度
                                         ↓ 主机输出交接
GPU 逐帧 P2/P98 → GPU 局部液化位移场
                     ↓ 与保留 RGB 整对提交
GLES 左右眼采样 → SBS 合成缓存 → 显示
```

局部液化将视差不连续处的背景采样坐标连续拉伸到前景边缘，以羽化范围分散形变。它用已有背景纹理覆盖新露出区域，不重建真实隐藏背景；代价是背景拉伸、直线弯曲或果冻感。严格同帧避免运动人物轮廓与旧深度错位，不能消除网络自身误差，也不保证物体内部完全刚性。

两个捕获槽约束在途工作和内存所有权，GPU 工作可与后续捕获/串行推理重叠。重复配对帧复用 SBS FBO，避免重复完整合成；每眼 1080p 缓存额外约 15.8 MiB。严格配对会增加显示帧龄，音频目前没有额外延迟补偿。性能不能只看 NPU 单次耗时或深度/RGB PTS 差为零。

## 保留与暂停的路线

| 路线 | 决定与理由 |
| --- | --- |
| 原始 gather33 像素偏移及补洞 | 保留源码和网页对照，作为回归基线；不删除，不作为主路线的自动回退 |
| 518/12 Hz、392 非配对双档；CPU/历史平滑 | 已被本次主路线取代为历史对照；高分辨率不能代替时序对齐 |
| 透视网格、全局连续弹性网格 | 保留网页实验；全局纹理形变与人物胖瘦问题使其不优先 |
| 参考项目完整 Quality、前后帧时序补洞 | 保留复现与负结果，用户观感未优于选定方案；暂停主线投入 |
| iw3 学习型 warp、视频/动画特化深度、生成式补洞 | 研究储备，未在本项目原生验证，不列为近期必做 |
| 完整 QNN 注册共享缓冲 | 下一阶段性能方向；独立验证不等于产品已零拷贝 |

完整算法原理、优缺点、论文和历史数值见[归档路线比较](archive/2026-09-14-sbs-route-survey.md)。归档仅撤销其现行指导地位，不删除实验代码、网页预览或性能证据。

## 实施顺序与验收

先收敛正式播放器恢复、显示生命周期、兼容编码和字幕/音频同步，完成同配置 20–30 分钟有效连续播放；再接完整模型共享缓冲，以真实帧龄、队列等待、成对更新率和热态测量决定后续优化。任何算法改动均与固定基线做同素材同强度对照，分别评估轮廓鬼影、跳边、背景形变、深度感和舒适度。

最新短测为 21.38 Hz / 119.604 秒，不能承诺稳定 24 Hz；旧测试不能替代新配置长测。构建、诊断和明确未验收项见[实时 SBS](REALTIME_SBS.md)。
