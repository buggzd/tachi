# 实时 SBS 技术路线总览

截至 2026-09-14，代码基线 `105804b`。本文汇总 tachi 已尝试、保留和待探索的算法及数据通路，供后续选择实验使用；不把网页原型或独立 benchmark 写成播放器已经具备的能力。构建和产品选项见 [实时 SBS](REALTIME_SBS.md)，历史原始数据以文末链接为准。

## 1. 问题如何拆分

```text
Media3 硬解 → 原始视频 GPU 纹理 ───────────────────────→ 左右眼合成 → 呈现
                    ↓                                      ↑
             降采样 / CHW / 归一化 → NPU 深度 → 范围归一化 / 时序稳定
                    └──────── 媒体 PTS、缓冲所有权与完成同步 ──┘
```

这里有两种不同的归一化：模型输入的 RGB 标准化，与模型输出的相对深度范围映射。前者服务于网络数值，后者决定立体效果的尺度。

画质问题也需要拆开：模型轮廓估计不准、逐帧深度漂移、视频与深度错时、左右眼遮挡竞争、缺失背景填充，是不同原因。提高分辨率不能单独解决错时；平滑深度可能增加迟滞；每个输出像素都有颜色也不代表背景正确。

本文状态含义：**原生已接入**指当前开发分支或明确标注的日常实验配置；**独立实机**指手机 benchmark；**桌面已测**包含离线算法和网页；**仅调研**未运行相关模型；**待做**尚无本项目实现。历史产品实现与当前默认配置分开描述。

## 2. 深度模型、分辨率与范围

| 路线 / 状态 | 原理与实现 | 性能影响及证据 | 优点 | 缺点 / 边界 |
| --- | --- | --- | --- | --- |
| 单帧 Depth Anything V2 Small / 原生已接入 | 固定形状、校准后的 U16/I8 QDQ 图，经 ORT QNN 在 HTP 推理；按采样节拍生成深度 | 早期 266×154 约 18.29 ms；当前日常实验 392 约 31.81 ms、518 约 56.37 ms；不是同一次对照 | 已打通手机，成本可控 | 单帧网络没有视频一致性保证；量化、细线和动画域误差仍存在 |
| 提高真实推理分辨率 / 实机已测 | 重新固定输入形状并校准模型，非放大旧灰度图 | 已跑通最高测试档 644×364，推理约 99.33 ms；770×434 在会话创建时分配失败 | 用户反馈高分辨率轮廓更好 | 算力、编译内存上升；644 不是硬件绝对上限，770 失败也不证明所有部署方式均不可行 |
| P5/P95 + 范围 EMA / 原生已接入 | `d=clamp((raw-low)/(high-low),0,1)`；精确分位数，范围 EMA 系数 0.15 | 已移入 GPU；详见数据通路节 | 抑制极值，稳定相对视差范围 | 不能输出米制距离；构图改变仍可能造成尺度漂移 |
| P2/P98 + 强度旋钮 / 网页已实现 | 网页对照从原始深度重新生成 2%/98% 数据；旋钮改变双眼位移幅度 | 主要是范围选择，不减少模型成本；没有手机性能对照 | 保留更多深度尾部，可自行比较立体强度 | 原生仍为 P5/P95；网页仍逐更新平滑范围，并非整镜头固定范围 |
| 整镜头范围、鲁棒尺度注册 / 部分桌面实验 | 整镜头固定范围仅参考调研；Huber 仿射注册已做合成对应点测试 | 20% 错配时视差 MAE 由普通拟合 1.052 降至 0.039 px；未接完整时序管线 | 可抑制逐帧尺度呼吸 | 预读需延迟；真实纵深运动可能被错误当成尺度漂移 |
| 米制深度与物理视差 / 待做 | 使用可信尺度、相机内参、虚拟眼距和会聚距离，按投影几何生成位移 | 当前无校准或端侧性能证据 | 有机会跨镜头统一距离解释 | 普通电影常缺相机参数；动画本身不一定符合真实投影，米制模型也不能自动解决这些歧义 |
| 视频深度模型 / 仅调研 | Video Depth Anything 用跨帧注意力；FlashDepth 用因果状态及双分辨率；RollingDepth 用多跨度估计和尺度对齐 | 无本项目手机数据；论文桌面 GPU 帧率不适用于 QNN | 从模型内部约束时序，可能减少后处理负担 | 状态、窗口、显存、算子和量化支持需验证；未来帧窗口增加等待 |
| 动画特化 / 仅调研 | See-through 微调 Marigold，学习 Live2D 部件绘制顺序伪深度；可研究离线排序监督或蒸馏 | 未下载运行该大模型，无手机数据 | 对头发、脸、衣物等遮挡关系有领域先验 | 图层次序不等于等间隔空间深度；角色插画结果不能外推整集背景与时序 |

分辨率扫描中的 518 约 8 Hz 是旧 CPU 稳定管线结果；后续 GPU 和流水线优化后，日常实验已达到 12 Hz，不能用旧报告否定新结果。详细条件见 [分辨率扫描](performance/2026-09-13-resolution-sweep/README.md)。

## 3. 深度稳定与运动对齐

| 路线 / 状态 | 原理与实现 | 性能影响及结果 | 优点 | 缺点 / 边界 |
| --- | --- | --- | --- | --- |
| 同坐标历史融合 / 原生已接入 | 范围平滑后融合历史；深度差 ≥0.12 拒绝历史；颜色变化以连续权重控制当前帧比例；切镜和生命周期重置 | GPU 数值实现与 CPU 对照最大 8 位误差 1；没有运动补偿 | 抑制静态噪声，不需要光流 | 同色物体移动、迟到深度仍可能残留或跳边 |
| 历史裁剪 / 桌面消融，未采用 | 仿照时序重建，使用当前 3×3 深度范围裁剪历史；还试过更积极释放和连续深度门限 | CPU 原型额外约 0.3 ms；部分真实代理量退化 | 有机会拒绝错误历史 | 不能照搬 DLSS/FSR；本项目深度估计不是引擎提供的真值深度和运动向量 |
| 外观门限连续化 / 已采用 | 只平滑颜色变化门限，保留大深度变化立即拒绝 | 合成浅轮廓新露出 MAE 改善约 24.8%；低对比快移压力场景却从 0.2937 增至 0.6104 px | 减少门限附近突变 | 有明确负结果，不能称全面消除鬼影 |
| 时间常数滤波 / 桌面已测，未替换当前固定系数 | `alpha=1-exp(-dt/tau)`，比较 80/160/320 ms | 8 Hz 小阶跃中，160 ms 配置达到 90% 的时间约 250 ms，原固定系数约 625 ms | 不同深度频率下响应更一致 | 更快跟随会保留更多噪声；仍不识别运动 |
| DIS 光流传播深度 / 桌面已测，未原生接入 | 双向流、前后向一致性和光度门控；迟到深度沿有界历史逐段传播到当前帧 | M4 低分辨率双向流约 1.56 ms，传播约 0.24 ms；合成轮廓误差下降约 63% | 直接针对视频与深度错位 | 新露出区域缺历史，误差仍高；需计入运动输入获取成本，手机未测 |
| 保边上采样 / 桌面已测 | Guided filter、联合双边细化；另有网页颜色引导邻域选面 | CPU 960×540 原型约 4.23 / 20.35 ms；测试中 Guided 未改善边界，双边边界 F1 退化 | 理论上可用 RGB 边缘提高低分辨率轮廓定位 | 纹理边缘不一定是深度边缘；这不是完整 JBU 论文复现，GPU 高效版本仍待评估 |

当前没有通过冻结运动、压平深度或自动切换平面来获得“稳定”的策略。已有深度慢时继续持有有效结果，但这仍会增加错时，不能作为画质问题的终点。具体消融及评价反例见 [伪影评价](performance/2026-09-12-artifact-evaluation/README.md) 与 [桌面优化](performance/2026-09-11-desktop-optimization/README.md)。

## 4. 从深度到双眼：投影、补洞与连续扭曲

原始像素路线每眼目标位移为 `±W × 0.016 × strength × (d−0.5)`。在每眼宽 1920、强度 1 时，最大单眼位移绝对值为 15.36 px，左右眼总差最大 30.72 px。系数是立体舒适度映射参数，不是测得的真实眼距。前后景位移不同，会让原来被前景挡住的背景在新视角露出；单帧没有这些颜色，形成洞。

| 路线 / 状态 | 实现方式与原理 | 性能影响 | 优点 | 缺点 / 观察 |
| --- | --- | --- | --- | --- |
| 原始 gather33 像素偏移 / 原生保留 | 对目标像素检查横向 33 个源候选，计算前向投影误差；覆盖误差 <0.75 px 时近景优先，无覆盖时选误差最小者 | 当前日常双眼 GLES 绘制均值约 7.2 ms，包含该配置的绘制工作 | 局部搜索、结果稳定可控，是用户目前偏好的补洞基线 | 隐式填洞没有可靠远背景保证，会拉长前景颜色；候选切换会跳边；本身无 RGB 历史去鬼影 |
| 前向 splat / 早期网页实现 | GPU 点投影、深度测试近景优先；颜色引导深度上采样，横向寻找更远邻居填洞 | 有桌面功能验证，不能替代当前手机基线 | 可见性与洞位置比较明确 | 离散覆盖、前景膨胀和洞搜索容易带来伪影 |
| 少次逆投影 / 桌面已测，未采用 | 2 次反求源坐标，或 4 次迭代加局部搜索 | M4 双眼静态测试约 0.45–0.82 ms；gather 约 2.44–3.71 ms。混合方法薄线场景约 2.43 ms | 平滑区域减少采样次数 | 深度不连续处可能选错表面；纯逆投影薄线测试约 22.7% 像素明显不同，不能按速度直接替换 |
| 连续透视深度网格 / 网页已实现 | 用 `Z=1/(0.5+d)` 反投影顶点；平行双相机、会聚和投影纹理；Z-buffer 判遮挡 | 多三角形、顶点采样，减少逐像素搜索；无手机计时 | 接近“深度置换曲面 + 原相机投影贴图”，方便观察几何 | 深度断层被三角形连接成斜面，纹理拉伸；连续网格也不天然保证屏幕全覆盖 |
| 断边透视网格 / 网页已实现 | 丢弃顶点深度跨度超过阈值的三角形，洞显紫色 | 增加判定，实际性能未测 | 避免跨前后景的斜面连接 | 显式暴露更多洞，阈值跨越会闪烁，仍需要补洞 |
| 简化参考边缘 splat / 网页已实现 | 颜色引导 5×5 选面 → 多子像素覆盖 / 近景优先 → 从远背景边界外选择颜色补缺失覆盖 | 三个 WebGL pass，最远搜索 64 px；没有手机性能证据 | 比原始隐式填洞更明确地区分背景与覆盖 | 用户反馈背景补洞不如原始；不是完整参考 Quality |
| qinglong 完整 Quality 核心 / 桌面离线复刻 | 区域划分 → RGB 测地边界归属 → 单侧深度重采样 → 前景 matte 扩张 → 16 子像素前向 splat → 覆盖 / 前景排除 → Telea 背景代理与合成 | CPU Torch/C++、多阶段离线生成；未做可归因的移动端或纯核心耗时测量 | 保留上游核心与源码哈希，能够公平检查参考算法 | 用户反馈 Quality 仍不好；Telea 不知道真实遮挡内容，细线和颜色扩散仍有问题 |
| 前后帧背景补洞 / 桌面离线实现 | 取 ±1、±3 帧；低分辨率双向 DIS 筛选可见背景，RANSAC 仿射外推背景运动；深度 / 前景排除后，只替换缺失覆盖，失败保留 Quality | 24 fps 下最远未来 3 帧约需 125 ms 预读，另加计算与同步；未接原生 | 使用视频中实际出现的背景颜色，可减少凭空拉伸 | 洞内没有可靠直接光流；仿射不适合复杂视差/非刚体；前后帧未出现的背景仍无法恢复 |
| 无洞弹性网格 / 最新网页实现 | 屏幕空间每行目标格宽 `du + eye×0.016×strength×Δd`，限制为原宽 0.2–5 倍，再归一化到固定两端；横坐标严格递增，GPU 连续三角形覆盖 | CPU 构造并缓存网格，上传双眼 RG32F 坐标；97/193/385 列可选；无手机或完整性能 A/B | 无折叠且全覆盖，无需补洞或历史颜色；保留所有旧策略可比较 | 通过拉伸 / 压缩换覆盖，会有果冻、弯线与会聚变化；常量深度变成恒等映射；不是严格原始位移公式，目前尚无用户评分 |
| 背景局部液化 / 网页已实现 | 识别深度跃变露出侧，只增加远景位移；沿背景距离平滑衰减，羽化与强度可调；剩余缺失沿用 gather | CPU 缓存位移场、GPU 搜索覆盖，尚无手机计时 | 限制背景局部形变，不做颜色模糊；原前景视差保留 | 不保证无洞，低分辨率边界仍会错选或跳动，背景纹理可能弯曲；待主观评分 |
| iw3 RowFlowV3 / 仅源码调研 | 网络根据深度、强度、会聚预测横向反向采样偏移，再 `grid_sample` RGB；可低分辨率预测坐标 | 未下载权重、未运行，没有 QNN 成本或算子支持证据 | 学习采样场可能比解析填洞更好；无需逐输出像素显式空洞 | 默认偏移预测不输入 RGB；可拉伸或重复背景；RowFlow 不是视频光流，也不是三角网格 |
| iw3 MLBW / 仅源码调研 | 多层偏移与 softmax 混合，多次反向采样；部分模型有洞掩膜与修补路线 | 预计增加推理、采样及中间缓冲，未测 | 可以表达多层边界混合 | 学习误差、层混色与时序仍需评估，不能等同默认 RowFlow |

完整 Quality 复刻范围是隔离的参考渲染核心，没有运行原项目应用、安装器或其深度模型。输入采用本项目缓存的 392 深度及 P2/P98，不能称整套上游端到端输出完全一致。原项目未启用的 planner / exemplar 路径也不能算已复刻并运行。

时序补洞的三个片段中，缺失覆盖像素采用前后帧颜色的比例约为 26.41%、63.75%、67.92%。这是**采用比例，不是背景恢复正确率**。当前失败回退是完整 Quality，不是原始 gather；后续可将同一时序候选接到原始补洞基线上单独比较。

## 5. CPU、GPU、NPU 与流水线

| 路线 / 状态 | 实现与原理 | 性能证据 | 收益与代价 |
| --- | --- | --- | --- |
| HTML video + JS / 历史实现，网页实验保留 | 浏览器解码、Canvas 或 WebGL 取帧、跨桥推理、双眼处理 | 早期性能受读回、桥和调度影响；不能与新管线不同模型的数字直接算整体倍数 | 开发和对照方便，底层缓冲及时钟控制有限；Android 已由 Media3 拥有播放 |
| Media3 + OES + GLES + QNN / 原生已接入 | 硬解输出纹理；2D 与 SBS 共用原生播放器，控制 UI 留在前端 | 已实机播放并测量端到端 PTS | 减少 JS/桥路径，支持原生解码；仍需处理格式、字幕、音画同步及生命周期 |
| GPU 降采样 + PBO / 桌面验证并演进为原生取帧 | GPU 输出小图，fence 后获取结果；满槽跳过采集 | M4 Canvas 均值约 8.60 ms → 同步 GL 3.06 ms；PBO 调用工作约 0.73 ms，但帧龄约 17 ms | 降 CPU 阻塞；异步等待不是消失，手机结果须单独测 |
| GPU 深度稳定 / 原生日常实验已接入 | compute 精确分位选择、范围融合、颜色门控与浮点历史，输出量化深度纹理 | 旧 518 CPU 后处理约 20.87 ms → GPU 提交约 0.39 ms；同轮深度 7.78 → 8.79 Hz | 大幅减少 CPU 工作，可与后续推理重叠；提交耗时不等于 GPU 完成延迟 |
| GPU RGBA→CHW / 原生日常实验已接入 | RGB 查表完成模型标准化，compute 写 Float32 CHW，经读回交给 ORT | 同轮 518 CPU 输入工作 3.0067 → 0.0581 ms；捕获到完成 95.58 → 91.24 ms | 删除 CPU 像素循环；仍读回浮点，12 字节/像素而非 RGBA 的 4 字节，不能叫零拷贝 |
| 双捕获槽 + 固定输出缓冲 / 原生日常实验已接入 | 每槽独立颜色快照和输入，NPU 串行，有界交接与代际失效；复用主机输出 | 早期 392 单槽 12.27 → 双槽 19.08 Hz，最终查表配置 19.91 Hz；与后面的日常 21.68 Hz 分属不同实验 | 重叠捕获和推理，减少分配；槽更多也可能增加排队帧龄。固定主机输出不等于注册共享内存 |
| 原生 QNN 共享缓冲 / 独立实机通过，未接播放器 | AHardwareBuffer BLOB 同时注册为 GPU SSBO 与 QNN I/O；完整 518 模型三组参考输入循环 | 100 次测量校验通过；共享 graphExecute 均值 56.28 ms，普通主机 57.08 ms；GPU→HTP→GPU 校验循环 62.13 ms | 证明完整图可跨 GPU/HTP 共享，无逐轮图像主机拷贝；未包含实时预处理、稳定和 SBS，目前同步方式仍含 glFinish，不能直接当产品收益 |
| 动态 12↔24 Hz / 待做 | 按推理、队列、PTS 和温控预算改变深度采样节拍，需滞回和最短保持时间 | 当前是静态双档，尚无动态策略测试 | 可能兼顾负载与响应；不应频繁切分辨率或压平视差，避免用户已反对的效果跳变 |
| 原生未来帧预处理 / 待做 | 有界视频预读，深度与视频按 PTS 一起延迟，保持音频/字幕同步 | 仅桌面未来帧补洞已实现，无原生结果 | 可减少深度错位并提供真实背景；增加内存、起播/seek 延迟，不能无限堆缓冲 |
| Apple CoreML / 桌面负结果 | ORT CPUAndNeuralEngine、MLProgram | 同一浮点模型 CPU 约 25.82 ms，CoreML 约 33.92 ms，存在 CPU 分区 | 不继续作为骁龙模拟路线；选择 ANE 配置不证明全图运行在 ANE |

## 7. 画质结论与仍未尝试的方向

用户目前偏好更高分辨率，原始补洞的观感优于参考简化版及完整 Quality；轮廓鬼影、跳边和深度抖动尚未解决。早期 A–D 评分每片段随机映射，不能把“D 较好”固定解释为某个参数。最新弹性网格尚待评分，也没有移动端成本证据。

接下来应分别验证以下问题，而不是一次叠加所有候选：

1. **连续扭曲是否值得交换几何形变。** 保持相同深度、强度和帧时序，比较原始 gather、弹性网格及其密度，检查人物轮廓、直线、背景呼吸和快速横移。网格全覆盖测试只证明无洞，不证明视觉正确。
2. **时序颜色是否胜过空间猜测。** 将可靠背景候选与原始填洞组合，并比较仅过去帧与允许未来帧；分别记录供体采用率、真实颜色误差和失败回退。目前没有原生多帧背景图集、分层深度图或可靠遮挡重投影。
3. **共享缓冲能减少多少真实帧龄。** 将完整模型独立验证接到 OES 输入、稳定及绘制；用显式同步与有界槽位取代验证用全局等待，比较 PTS 长尾和持续运行，而非只比较 graphExecute。
4. **更好的模型是否值得额外成本。** iw3 学习型 warp、视频深度、动画排序蒸馏均未实跑；先做固定片段离线画质及算子检查，再决定是否投入 QNN 适配。生成式补洞、分层场景重建也尚未实现，可能改善内容缺失，但有一致性、算力与虚构纹理代价。

量化必须同时记录空间视差误差、轮廓带/新露出误差、时间变化误差和阶跃响应，防止“更模糊、更迟钝”虚假胜出。有新视角真值时再比较 RGB 重建、感知质量；真实片源没有左右眼真值时，光流对齐残差只是代理量。主观测试保持匿名、同帧、同强度，并单独评分鬼影、跳边、果冻、深度感与舒适度。指标和文献见 [伪影评价研究](archive/2026-09-12-artifact-metrics.md)、[DLSS/FSR 借鉴边界](archive/2026-09-12-dlss-fsr-sbs.md)、[视频深度与动画模型调研](archive/2026-09-11-realtime-sbs-research.md)。
