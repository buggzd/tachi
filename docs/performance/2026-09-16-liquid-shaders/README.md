# 液化扩散融合与最终重建采样复用

## 结论

两个候选均保留为 opt-in，暂不纳入 daily liquid 默认。完整 tachi 三轮约三分钟得到 23.74 / 23.61 / 23.53 Hz；没有明确端到端提帧。采样复用的 GPU 渲染滚动均值中位数低约 3.3%，但捕获到绘制和软件 PTS 落后未改善，不能用该局部指标宣称整条管线加速。手机已恢复基线 APK，保留此前采用的捕获顺序优化。

## 实现与画质约束

基于 `10e4833` 捕获顺序版本，分别测试两个独立开关：

- `-PliquidFusedRounds=true`：12×12 shared tile 含两像素 halo，先计算 10×10 中间场，工作组 barrier 后写 8×8 内区。八轮 Jacobi 不变，含 seed 的 dispatch 从 9 次降至 5 次。边缘无效 lane 仍经过 barrier；两轮的权重、累加顺序和限幅保持原式。
- `-PliquidCacheSamples=true`：最终重建搜索保留前一个线段终点的深度与位移，仅当下一点浮点坐标完全相等时复用。插值、前景选择、搜索范围和 fallback 不变。更激进的双行数组缓存保存在 `StereoLab/experiments/shaders/liquid-row-cache.frag`，未选为产品候选。

维持 392×224、P2/P98、严格同帧双槽、0.85 / 96 px / 65%、FP32 与捕获后提交液化。原始 shader 保留；两个开关的通用默认均为 false。

融合增加 halo 的重复算术和 shared memory 用量，减少 dispatch 不必然更快。终点缓存也增加分支和寄存器存活，必须以完整播放收益判断。

## GLES 等价验证

`StereoLab/experiments/verify_liquid_gpu.cpp` 在实际 Android GLES 3.1 工作组运行。覆盖 1×1、非整工作组尺寸、垂直边缘、断行边缘、噪声、518×294，以及高动态 579 帧的 392×224 深度；RGB 为 1920×1080 合成高频纹理，测试双眼与调试覆盖层。

所有案例位移场最大误差为 0；采样复用及两项组合的 RGBA8 输出通道差为 0。这是这些输入上的数值等价证据，不是所有实际视频的主观画质验收。

复现：使用 Android NDK 的 `aarch64-linux-android26-clang++` 编译该文件，参数 `-std=c++17 -O2 -static-libstdc++ -lEGL -lGLESv3`。将程序、四个原始/候选 shader 放入设备可执行目录，运行 `verify <shader目录> <可选392×224原始R8深度文件> <重复次数>`。须检查退出码，再读取 JSON。

隔离 GPU 交替顺序 15 次测量中，实际深度案例扩散 1.803→1.992 ms，重建 9.134→8.805 ms；其他输入存在反向变化。计时是 glFinish 主机墙钟中位数，非产品 GPU 阶段，也不作为稳定加速结论。早先双行缓存采用不同顺序，不与该轮直接比较。

## 完整播放器短测

以 tachi MainActivity 实际 Jellyfin 播放、外接 RayNeo Air 3s 为最终对照；独立 SbsFixtureActivity 仅为辅助，不混入产品统计。同一匿名片源 H.264/AAC HLS + ASS、1920×1036、23.976 fps，`c2.qti.avc.decoder`；SM8850/V81、外接 3840×1080，每眼重建目标 1920×1080。每轮均过滤媒体 60–240 秒、选择最长连续 playing/ready/valid/stereo/aligned 段，实际约 178.5–178.7 秒（1 Hz 采样边界）。准备、暂停和 seek 不计入窗口。

除明确标为 PTS 均值外，阶段 ms 是每秒导出的滚动均值的中位数；GPU 渲染含实际该计时区间的工作，不是独立重建 kernel 计时。配对与合成更新计数的差不能直接视为物理丢帧。三轮 PTS 缺失、未知深度、未来深度增量及字幕错误样本均为 0。

100 秒呈现子窗口采样无错误，present 间隔 P95 约 16.60 ms，最大 49.80 / 49.81 / 66.41 ms；采样间隔最大 1.70 秒以下。电池起止约 30.2–32.6°C，thermalStatus 采样均 0；充电顺序运行并不等于固定 GPU/NPU 频率。

每秒日志中的阶段统计是滚动均值的采样分布，不是逐帧分布；捕获到绘制开始不含 GPU 完成、合成器和物理屏幕发光时间。SurfaceFlinger 刷新包含重复缓存，不能当转换帧率。三轮顺序短测未控制频率和温度，不能推导续航或长期稳定 24 Hz。

Jellyfin 曾出现一次应用 NETWORK 提示；复核电脑和手机请求均为 HTTP 200，重新进入 tachi 后目录正常。此前“服务器不可达”的判断不成立，单次加载失败原因未定位。

## 验证边界

三个 APK 均完成 JVM 测试、lint、组装及 verify-android；汇总脚本的三个用例通过。本轮不声明完整设备回归矩阵、冷启动 UI 裁切、插拔、物理音画同步或长时温控通过。原始视频、日志、APK 位于忽略目录，不入 Git。
