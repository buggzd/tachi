# 24 Hz 优化：采样诊断与液化邻域复用

基于 `f7c7f42` 主路线，保持 392×224、逐帧 P2/P98、严格同帧、0.85 / 96 px / 65% 和八轮平滑。目标是提高成对输出并减少等待，不用加深队列或降低画质获得帧率。

## 改动

- `NativeVideoView` 的 `captureAdmission` 提供累计候选数、节拍跳过、读回 fence 阻塞、槽位耗尽和已提交数。分类按节拍→fence→槽位顺序互斥，代表观察到的阻塞原因，不是独立阶段耗时；有效片段内取差值。计数随 View 生命周期，不假定 seek 后清零。当前同 APK fixture 的完整 render JSON 可采集，不代表手机导出白名单已包含新字段。
- 液化八轮扩散采用 8×8 工作组、10×10 含 halo 的共享深度与位移缓存。完整工作组每轮原邻域需要最多 576 次深度和 576 次位移纹理读取，改为各 100 次协作加载，再读取共享内存；中心深度和 seed 等读取仍存在。减少纹理指令不等于同比性能提升，原纹理缓存与新增 barrier/共享访问都会影响实际结果。
- 保留 FP32、RGBA32F、中间结果、迭代次数、邻居求和顺序和边界剔除。图外线程也参与 barrier，然后退出，避免非整工作组尺寸死锁。缓存 phase uniform 地址，减少重复驱动查询。

## 验证与限制

app/native-video JVM 测试、lint、APK 装配与资源验证通过，见[构建与 APK 哈希](build-verification.json)。ESSL 3.1 compute 通过 glslang 编译检查。桌面 WebGL 使用每片元私有 tile 模拟同样的 halo 索引，常量、边缘、缺失行、噪声和真实 579 帧对照 CPU；增加 131×67 非整工作组尺寸与正确的字节上传对齐，最大位移误差小于 0.000007 px，见 [数值记录](desktop-parity.json)。这个测试不验证 Android 工作组同步或性能。

无线 ADB 重试成功，完成诊断基线、共享 tile 和共享 tile + PTS 节拍三版的顺序短测。使用相同本地片源，手机 fixture 的 SBS 预览（每眼合成目标仍为 1920×1080），没有完成外接眼镜长测。比较媒体位置 20–110 秒内各自最长连续 `playing + valid + stereo` 段，详见[匿名汇总](device-comparison.json)。

最终版本相对本轮基线成对更新约增加 29.8%，仍未达到 24 Hz。后处理/驱动排队与槽位占用仍值得优化；不能把阶段滚动统计相加为端到端时间。测试顺序未随机化、未做 A/B/A；设备充电，基线后记录电池 33.3°C、最终测试中 35.0°C，不能据此声称功耗收益。三版窗口并非完全相同的边界帧，也不属于严格温控因果实验。

PTS 节拍只用于已知 PTS 的 aligned liquid 采样选择，采集/推理耗时仍用单调墙钟；未知 PTS 保留原墙钟路径。按源帧时间选择而非线程到达时间，可避免 23.976 fps 片源因调度抖动而错过 24 Hz 采样截止。换源代际或时间回退重置节拍，只有捕获获准才推进截止，不增加槽数或缓冲深度。JVM 测试覆盖 23.976 fps 全帧选择、30 fps 选择 24 Hz、阻塞不消耗机会以及 seek/换源/未知 PTS。

原文件选择失败包含覆盖安装后的残留任务，以及搜索键盘遮挡确认按钮两种情况。重建测试任务、逐步操作并收起键盘后可选片。UI 自动化 dump 在动态界面可能返回 idle 错误并留下旧 XML；此时不能把旧 XML 当当前页面。重试没有清空应用数据。

原始日志与 APK 在忽略目录保留；提交的汇总不含媒体名、账号、地址或画面。旧 21.38 Hz 属于[上一轮](../2026-09-15-native-liquid-retest/README.md)不同环境，不与本轮算提升比例。本轮没有完成正式 Jellyfin、字幕/音频同步、外接显示、长时温控和完整设备矩阵；后续仍需这些验收。

构建 `scripts/build-sbs-experiment.sh liquid`，手机已安装 PTS 候选，源码保留严格同帧与原画质参数。下一轮优先测量/缩短槽位的 GPU 等待与完成交接，再判断是否需要采样机会重试或共享缓冲；不能靠扩大队列换取更高帧率。

## 继续优化：补采机会与按配对结果绘制

在 `e74904f` 基础上，aligned liquid 被 fence/槽位阻塞时记录当前锁定 OES 帧的 PTS 和代际。重复绘制或 GPU 深度完成交接时，只要仍是同一帧、没有新 decoder 帧待消费、代际有效且采样开启，就允许重试。成功后清除机会；新帧或代际变化淘汰旧机会。保持双槽上限，不增加排队容量，不改变深度/颜色配对与源帧节拍。`retryAttempts/retrySubmitted` 记录尝试/成功，原 fence/slot 跳过只计新帧初次尝试；总 submitted 包含补采，不能再直接与初次跳过相加还原 candidates，应先减 retrySubmitted。

此外，GPU 深度处理提交时尚未有新配对画面，取消 aligned liquid 此处的额外 requestRender；接受新配对、decoder 帧和正常界面更新的绘制仍保留。旧非配对路径不变。

| 相同媒体区间指标 | 上一版 PTS | 加补采 | 再去掉额外绘制（保留版） |
| --- | ---: | ---: | ---: |
| 有效窗口秒 | 89.168 | 88.243 | 89.145 |
| 成对更新 Hz | 21.207 | 23.118 | 23.479 |
| 采样软件视频落后均值 ms | 76.856 | 81.776 | 70.295 |
| 采样软件视频落后 P95 ms | 125.125 | 125.125 | 125.125 |
| 捕获到上传末次滚动均值 ms | 74.183 | 85.904 | 81.084 |

最终比上一版更新率增加约 10.7%，达到 23.976 fps 片源的约 97.9%，未宣称稳定全帧或物理呈现 24 fps。补采等待发生在 capture 时间戳之前；captureToUpload 不包含这段时间，不能只凭它判断端到端收益。软件 PTS 落后独立采样，仍不代表音频/屏幕光学延迟。充电状态下，本轮中记录电池 35.1→36.0→37.0°C；没有随机顺序和热态控制，提升幅度是顺序实测结果，不是严格因果或持续热态保证。[汇总](retry-comparison.json)保留各窗口、计数与末次滚动统计。

最终候选 app/native-video JVM 测试、lint、APK 装配/资源检查通过。手机 fixture 回归确认 seek 后恢复配对，暂停稳定期计数不增长，恢复后增长，SBS→2D→SBS 后继续有效输出；配对 PTS unknown/future 保持 0，见[回归快照](retry-regression.json)。这些只是 fixture 渲染模式切换，不是 USB 硬件显示切换或完整设备矩阵。正式播放器恢复、音画/字幕、外接眼镜及 20–30 分钟验收仍未完成。

当前手机已安装保留版。下一步以剩余约 2% 源帧缺口和长时热态为目标，分解读回/后处理完成观察与 GPU 队列延迟；注册共享缓冲仍是后续端到端方向，避免继续增加缓冲深度。
