# GPU 轮询调度：三轮约 3 分钟对照

## 决定

保留 `gpuPollOffMain` 实验开关，默认仍关闭；保留新增调度诊断。独立线程有小幅收益迹象，但本轮不足以证明稳定提升，更没有达到稳定 24 Hz。手机最后安装带诊断的原调度包，播放已暂停。

## 范围与方法

代码 `dda3d7b`。SM8850/V81，RayNeo Air 3s 3840×1080，实际 tachi Jellyfin 播放，匿名同一集 H.264/AAC HLS、ASS，实际解码器 `c2.qti.avc.decoder`，1920×1036、23.976 fps。不是上一次 HEVC/VTT 直放片源，不能与其 22.54 Hz 直接计算增益。

三个版本顺序为原调度 A、独立定时线程 B、原调度 A2；每轮从开头播放，统计媒体 60–240 秒区间。1 Hz 日志边界造成有效窗口略短于 180 秒。初始化、操作、预热不计入该窗口；没有新增长测。均保持 392×224、逐帧 P2/P98、严格同帧双槽、GPU 液化 0.85／96 px／65%，不降质量。

B 仅改变 fence 轮询的定时来源，GLES 工作仍在原 GL 线程。定时唤醒包含请求的 2 ms，GL 排队和处理耗时均是主机侧观测，不能分离出准确的 GPU 完成时刻。

## 系统与验收限制

- 每轮另采约 100 秒 SurfaceFlinger 子窗口，1 秒请求间隔；实际最大采样间隔 1.86 秒。观察到的 present 间隔 P95 约 16.60 ms、最大约 49.80 ms。含重复缓存，不能当作转换帧率或完整物理丢帧统计。
- 充电，采集点电池温度约 30.4–32.4°C；三轮温度不同。thermalStatus 样本均 0，不证明不存在频率调整。
- 安装与播放可恢复，停止采集后确认 paused、有效配对保留。未覆盖完整插拔、后台、seek、独立线程退出/重建压力、音轨及同步矩阵。
- 第一次硬件切换后的目录 UI 正常；候选冷启动后目录出现放大裁切，原生视频画幅正常。未查明根因，也未确认两轮 WebView 合成负载完全一致；本轮不能宣布 UI 生命周期回归通过。
- ASS 无字幕错误上报不代表可见位置或独立音画同步正确；无光学和音频回录验收。

## 后续优先级

1. 最终 `gpu-liquid/render.frag` 的反向搜索对相邻源点重复读取深度和位移。先以数值和高动态画面验证等价性，再尝试减少重复采样；不改变补洞规则、参数或搜索精度。
2. 区分 GPU 执行、队列与完成观察。当前 fenceObserved 仍包含队列和轮询；新增指标没有完成硬件时间线分解。
3. 共享 QNN 输入/输出继续作为同步与带宽探索，但单次主机 map/copy 仅约 0.15 ms，不能假设消除它就能取得数毫秒收益；完整共享路径必须重新测量。
4. 单独修复冷启动 UI 裁切，再做后续性能对照。长时间观影由用户反馈。
