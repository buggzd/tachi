# 2026-09-12 原生播放首轮实机调试

基线 `70b6503`，测试对象为独立 `native-player-lab`，主应用没有改动或重新安装。
设备 SM8850 / 2509FPN0BC，Android 16，无线 ADB，充电状态。测试发生在手机屏幕，
没有进行眼镜 USB 模式切换；没有 NPU 消费者、深度偏移、HDR 或受保护视频。

## 结果与修复

- 既有 Jellyfin 动画片段的本地副本：H.264/AAC，1920×1080，23.976 fps，约 20 秒。
  通过电脑 HTTP 测试服务器及 ADB reverse 播放；随后在本地无重编码重封装为 HLS。
  这验证了播放器的 MP4/HLS 路径，不等于 Jellyfin 在线鉴权及服务端转码集成已通过。
- 系统记录实际视频组件为 `c2.qti.avc.decoder`，音频为 `c2.android.aac.decoder`。
  抽查的约 5 秒视频解码统计窗口中 Drop 为 0。没有完整 SurfaceFlinger 呈现轨迹，
  不能据此声称全链路零丢帧或零音画误差。
- 原始版本 20 秒结束时 UI 显示 175 张样本。按“距上次采样至少 83.33 ms”判定会被
  24 fps 解码节拍的微小抖动推迟一帧。改为固定时间点调度，错过的时间点直接跳过，
  不积累队列。色块片 50.305 秒得到 605 张；HLS 20.062 秒得到 241 张，约 12 Hz。
  这是目标深度采样率，不是视频渲染帧率，也不是已经测得 NPU 达到此速度。
- 实机复现“404 后新片源可以播放，但样本一直为 0”。错误路径原先永久关闭采样；
  现在用独立的临时暂停状态，打开新片源时恢复。最终 APK 重复 404→有效 HLS，
  采样恢复并正常结束。
- 暂停后进度和采样数保持；继续后恢复。暂停时向前 seek，进度从 21.367 秒到
  31.367 秒，仅更新一张新画面样本，然后保持暂停。seek 后媒体 PTS 对齐尚未验证。
- 前后台释放后，音视频组件均有 RELEASING→UNINITIALIZED 记录；返回为空闲状态，
  重新选源后采样正常。冷启动正常。屏幕旋转/独立 EGL 上下文丢失尚未验收。
- 修复 Android 16 边到边显示导致状态栏遮挡调试文字，并固定状态区域行数，避免
  计数位数增加时改变视频区域大小。

## 取帧耗时

最终 APK：一次 404 后打开 HLS、暂停/继续并播放结束；241 次成功读回。统计没有混入
此前色块片的样本，因为此次渲染器在成功读取 HLS 前没有取得任何视频样本。

| 阶段 | 均值 ms | P95 ms | 含义 |
| --- | ---: | ---: | --- |
| 小图提交 | 1.6714 | 2.3094 | FBO 绘制、PBO readPixels、fence 和 flush 的 CPU 墙钟耗时 |
| fence 完成被观察到 | 7.9419 | 18.0167 | 提交结束至后续渲染轮次发现 fence 完成，包含调度/轮询间隔 |
| 映射及复制 | 0.0914 | 0.1561 | PBO map、复制进复用直接缓冲、unmap 的 CPU 墙钟耗时 |

数值记录见 [sample.json](sample.json)。统计窗口上限 512 次，按渲染器实例维护。
各阶段 P95 不能直接相加当成整体 P95；fence 观察延迟也不是 GPU 着色器耗时。
未测解码到显示的总延迟、OES 纹理等待、显示合成 GPU 时间或将来 NPU 队列等待。
该结果支持去掉 WebView 图像桥后继续接入 QNN，不能和旧链路约 96 ms 往返直接换算
成相同条件下的加速倍数。本轮没有长时热态、非充电功耗或 4K60 测试。

## 方向与颜色

使用 1080p/24 fps 四象限片：左上红、右上绿、左下蓝、右下白。手机显示及 PBO
top-row-first 的四点探针顺序一致；左右同图预览中每眼均保持相同顺序与宽高比。

显式 BT.709 标注的测试片，手机探针分别为 `(255,0,0)`、`(0,254,13)`、`(1,0,253)`、
`(255,255,255)`；FFmpeg 同尺寸参考分别为 `(255,0,0)`、`(0,252,11)`、`(0,0,251)`、
`(253,253,253)`，每通道误差不超过 2。未标注色彩矩阵的初始片出现更大的色差，
不把该片当作颜色正确性的判定基准；未知色彩元数据、HDR、广色域另行验证。

## 复现与后续

构建命令见 [原生迁移维护文档](../../NATIVE_VIDEO.md)。安装独立实验 APK，使用 URL
输入或未来待测的系统文件选择器。测试服务器和真实片源仅保留在忽略的本地目录。
用 `adb logcat -s NativeVideoLab:I` 获取数值诊断；取帧统计没有 URL、账号或完整画面。
本次归档去除了真实片段的 RGB 探针，仅保留合成测试片的颜色数据。

五项 JVM 测试（缓冲所有权、失效代际、contain 几何、抖动节拍、统计窗口）、两模块
Lint 和 APK 组装通过。当前模块不在主应用依赖中，架构回归矩阵中的账号、字幕、
外接 Presentation、USB 及完整产品播放流程尚未覆盖，不能标记为整体迁移通过。

下一步先接现有 QNN 模型和深度纹理合成，维持单请求背压与正常慢帧时保持有效深度；
再测并发时延、深度帧龄、画质稳定性，并验证共享缓冲导入及 fence/cache 同步。
