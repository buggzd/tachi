# 完整 Quality 与时序补洞：桌面画质对照

本轮只验证离线画质实验与网页交互，不使用 ADB，不修改 Android 默认渲染器。

## 两条新增对照

- **完整 Quality**：隔离复用用户提供的 qinglong-vr-3d 相对深度渲染实现，MIT
  许可及 22 个实现文件的 SHA-256 随 [源码快照](../../../StereoLab/vendor/qinglong-quality/README.md)
  保存。初始化入口被替换为空，未运行上游应用、安装脚本或模型。实际执行区域
  求解、单侧上采样、前景 matte 扩展、16 级覆盖、遮挡和 Telea 背景修补。
- **Quality＋时序背景**：对原本缺失的覆盖，尝试从前后 1/3 帧取得真实背景；
  双向 DIS 可见背景匹配经深度/颜色/前后向验证后，用 RANSAC 仿射模型外推到
  遮挡区。候选失败时保留完整 Quality。它不是精确光流补全或三维背景重建。

输入为已有三个真实片源的前 96 帧，392×224 预计算深度、2%／98% 分位数范围
缓动、半帧率更新及两帧模拟滞后。每眼输出 1920×1080、固定原 1× 视差幅度。
参考软件的 stereo_strength=3.2 与每眼 0.016×(d−0.5) 对应。未重新运行深度模型，
未移植参考项目整镜头归一化或其他上游阶段。

原 gather33 使用 CPU 对等公式生成对照，OpenCV 与 GLES 插值舍入可能有细微差异。
所有网页对照统一编码为 H.264 CRF16；编码会影响细小边缘，不能当作无损像素比较。
源码不包含真实片源；输出、逐帧统计和截图在忽略的 `.local/samples/full-quality`。

生成器的 `qualityFrameSeconds` 包含完整渲染、额外未修补诊断渲染和缓存压缩，
不能作为单次渲染内核时间或手机吞吐。

## 验证范围

- 七个 Python 合成/契约测试：源码与二进制身份、零视差还原、16 子像素覆盖、
  未来背景恢复、完整覆盖不被修改、回退保持、切镜拒绝和相机平移（部分同一测试内）。
- 浏览器检查片段播放、暂停同帧切换、双眼/单眼与逐帧定位。
- StereoLab 原有单元测试与生产构建。

这些检查不证明真实片源画质提升。时序补洞仍可能在动态背景、非仿射运动、
深度错位和重复纹理处失败。来源图用绿/蓝区分未来/过去，紫色为原 Quality
回退，黑色为完整覆盖；统计含部分覆盖像素，不代表恢复了相同面积的完整背景。

运行方式见 [StereoLab 指南](../../../StereoLab/README.md#完整-quality-与时序背景补洞)。

## 本次生成结果

三个片段均为 96 帧；五种视图共 15 个 3840×1080 视频，帧数与尺寸检查通过。
三片段网页暂停切换、逐帧与双眼视图均通过。按双眼各帧的缺失覆盖像素累计，
时序采用比例分别为 26.41%、63.75%、67.92%；详见
[脱敏覆盖统计](coverage-summary.json)。比例包括部分覆盖，不能解释为恢复正确率。
