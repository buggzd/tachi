# 2026-09-12 原生 QNN → 深度 SBS 实机验证

基线 `873935d`；本报告对应随文提交的 native QNN 实现。设备 SM8850 / 2509FPN0BC，
Android 16，无线 ADB，充电状态。测试对象是独立 `native-player-lab`，主应用未修改
播放实现，也没有安装替换主应用或切换眼镜硬件模式。

## 已跑通的链路

Media3 / `c2.qti.avc.decoder` → SurfaceTexture OES → GPU 266×154 RGBA8 → PBO →
CPU CHW → ORT QNN HTP → CPU 深度稳定 → R8 纹理 → GLES 双眼 gather →
3840×1080 FBO → 缩小到手机预览。每眼真正渲染 1920×1080，深度小窗默认开启。
取样只使用原始 OES 视频，没有将 SBS 或深度小窗再次输入模型。

使用此前 Jellyfin 动画片段的本地副本，H.264/AAC、1080p、23.976 fps，循环拼接成
约两分钟 MP4；另测同片段本地无重编码重封装 HLS。经本地 HTTP 与 ADB reverse
播放，不是正式 Jellyfin 会话/鉴权集成。CPU EP fallback 显式禁用，QNN 图 I/O 量化
不卸载到 CPU。模型/ORT/QAIRT 哈希见 [sample.json](sample.json)。运行进程实际加载
`libQnnHtp.so`、`libQnnHtpV81Stub.so`、`libQnnHtpPrepare.so` 与 ORT；推理成功且状态
持续 ready。沿用已有 SM8850/V81 验证过的后端，没有替换模型或启用 CPU 推理。

## 正常并发结果

跳过前 5 秒，约 67 秒记录区间的深度纹理更新率 **11.95 Hz**，目标 12 Hz。
下表取正常阶段最后一条记录中的最近 512 次统计；随后才开启慢帧注入，不混入延迟数据。

| 阶段 | 均值 ms | P95 ms | 测量含义 |
| --- | ---: | ---: | --- |
| GPU 小图提交 | 15.0404 | 21.1495 | CPU 墙钟：FBO 绘制、readPixels、fence、flush；含驱动等待 |
| fence 完成被观察到 | 8.8846 | 15.0461 | 提交返回至后续轮询完成，含调度间隔 |
| PBO map / copy | 0.0648 | 0.0980 | CPU 映射、复制、unmap |
| RGBA → CHW | 0.9033 | 1.4224 | 批量 RGBA 复制、CPU 归一化、写入复用直接张量 |
| QNN 推理及输出读取 | 18.4294 | 19.9011 | session.run、输出 float 读取与 result 关闭 |
| 深度稳定 | 20.1955 | 24.3686 | 范围估计、外观门控与时间滤波、R8 输出 |
| 深度纹理上传提交 | 0.1295 | 0.2784 | CPU 直接缓冲写入与 texSubImage2D |
| 小图采样开始 → 深度上传 | 64.3965 | 73.2251 | 包含读回、工作线程处理及 GL 上传调度；不含此前解码等待 |
| GPU SBS 渲染区间 | 11.0309 | 11.9643 | 两眼 1080p gather、深度小窗和手机预览 blit |

GPU 数据来自 `GL_EXT_disjoint_timer_query`，记录窗口内 disjoint 为 0；异步查询，
不阻塞等待。该区间不包含输入小图读回或 SurfaceFlinger，也不能单凭小于 16.67 ms
就声称完整 60fps 播放已经通过。CPU 提交与 GPU 工作存在重叠，P95 不能相加。
GPU 计时会采样视频更新、深度更新及读回轮询触发的绘制，查询次数不是视频帧数。

抽查解码器约 5 秒统计窗口：约 118–121 帧推进，Drop=0。没有采集完整显示帧轨迹，
所以结论是该配置下管线持续工作，而不是已证明所有呈现帧零丢帧。

## 发现并处理的开销

初接时在 Java 内逐像素访问直接缓冲，预处理约 25 ms、稳定约 30 ms，深度更新只有
约 9 Hz。改成一次批量复制到复用 RGBA 数组，再用数组运算、批量写入 CHW 张量，
预处理降到约 0.9 ms，恢复目标约 12 Hz。不是“任何额外复制都更慢”；大量细粒度
直接缓冲访问比一次小规模顺序复制更昂贵。

当前较大的待优化项是 CPU 稳定处理与 PBO 提交等待。全尺寸 SBS 后取帧提交明显
高于早先小窗口数据，说明 PBO 不自动消除前序 GPU 依赖/驱动等待。下一步可验证
取样与合成的提交顺序、减少重复绘制、GPU 稳定处理和共享缓冲，不能先称为零拷贝。

## 功能与生命周期回归

- 深度小窗随实际片源更新，与画面结构对应。暂停截图中，排除小窗区域后，两眼比较
  160,040 个像素，其中 135,016 个存在差异，RGB 平均绝对差 4.806；两眼深度小窗
  RGB 差为 0。证明双眼不是简单复制且共享同一深度图，不是主观立体画质评分。
- 注入 250 ms 消费者延迟后，更新率约 **2.96 Hz**。seek 前的 19 条稳定阶段记录
  全部保持有效深度，记录帧龄 381–505 ms，没有超时回退。采样图像仍只有一个 lease。
- 慢帧期间 seek，观察到一条旧代结果被丢弃；新代深度恢复。此测试验证结果代际，
  尚未验证纹理时间戳与媒体 PTS 的精确关联。
- 暂停超过 30 秒仍保持最后有效深度，采样及上传计数停止，符合不自动回退的偏好。
- 有效视频 → 404 → HLS：错误时旧深度失效；有效片源恢复后 QNN 和 SBS 正常更新，
  HLS 20.063 秒取得 236 张深度样本。此段统计窗口混有此前阶段，不用它重算正常基准。
- 前后台退出后音视频组件均记录 RELEASING→UNINITIALIZED；QNN 关闭由工作线程
  排在在途操作之后。重新安装/冷启动后，完整模型初始化及播放再次成功。

固定数值摘要见 [sample.json](sample.json)，逐秒数值记录见 [trace.jsonl](trace.jsonl)。
归档去掉了实际画面的 RGB 探针及源地址；截图和片源保留在本地忽略目录/临时目录，
没有将媒体画面、模型、SDK 或 APK 提交到 Git。

## 验证边界

八项 JVM 测试、两模块 Lint、普通和 `-PnativeQnn=true` APK 构建通过。完整包已安装
到实机。最终打包关闭厂商/DSP 库的 AGP strip，模型与全部 9 个厂商库的 APK 内哈希
均与清单一致。上面的长记录早于这项打包修正；保留原始库的最终 APK 再次播放 HLS，
20.059 秒得到 239 次深度上传，QNN 均值 18.31 ms、GPU 区间均值 10.88 ms、
采样至上传均值 63.35 ms，详见 `sample.json` 的 `finalApkSmoke` 与 APK 哈希。

尚未覆盖正式播放器会话/字幕/上报、外接 Presentation/USB 模式、HDR/DRM、
其他编码格式、4K60、长时热态与非充电功耗。低分辨率深度、运动边缘和遮挡处理仍
需要主观与客观画质验收；当前滤波不是光流，gather 也不是隐藏区域重建。

完整构建和调试操作见 [原生播放维护文档](../../NATIVE_VIDEO.md)。
